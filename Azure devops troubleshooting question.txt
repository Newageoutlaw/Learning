How does Azure Web App Service integrate with Azure DevOps for continuous integration and deployment?


Azure Web App Service and Azure DevOps can be seamlessly integrated to achieve continuous integration and deployment (CI/CD). The explanation as follows:

Set Up Azure Web App Service: Azure Web App Service is a platform for hosting web applications. First, you create and configure your web app in Azure. This is where your application will be deployed and run.

Create a Web App in Azure DevOps: In Azure DevOps, you create a project for your application. Within the project, you set up a build pipeline and a release pipeline.The build pipeline defines how your code should be built, tested, and packaged.


Connect Azure DevOps to Your Code Repository: Link your Azure DevOps project to your code repository (e.g., GitHub, Azure Repos). This allows DevOps to fetch your code and trigger the CI/CD processes.


Configure Build Pipeline: In the build pipeline, you specify the steps to compile your code, run tests, and generate artifacts (compiled code, binaries, etc.). This ensures that your application is in a deployable state.


Set Up Release Pipeline: The release pipeline defines how your application should be deployed to Azure Web App Service. You specify details like the target environment, deployment slots, and deployment steps.


Define Triggers: Configure triggers for your pipelines. For example, whenever there's a code commit or a new release branch, the CI/CD process should automatically start. This ensures continuous integration.


Deploy to Azure Web App Service: Once the build is successful, the artifacts are passed to the release pipeline. The release pipeline then deploys these artifacts to your Azure Web App Service.


Monitor and Rollback: Set up monitoring and logging for your application in Azure. If any issues arise after deployment, you can quickly identify them. Azure DevOps also allows you to automate rollbacks in case of deployment failures

### Prometheus Interview Questions:

#### 1. *What is Prometheus, and how does it work?*
   *Answer:*  
   Prometheus is an open-source monitoring and alerting toolkit designed for reliability and scalability. It works by scraping metrics from configured targets at given intervals, storing the metrics in a time-series database, and enabling queries using PromQL (Prometheus Query Language). Prometheus is pull-based, meaning it actively scrapes data from targets rather than relying on targets to push data.

#### 2. *What are the key components of Prometheus architecture?*
   *Answer:*
   The key components of Prometheus include:
   - *Prometheus server*: Scrapes and stores metrics.
   - *Alertmanager*: Handles alerts generated by Prometheus.
   - *Pushgateway*: Enables short-lived jobs to push metrics.
   - *Exporters*: Translate third-party data sources into a format Prometheus can scrape (e.g., Node Exporter).
   - *PromQL*: The query language used to retrieve data.

#### 3. *What is an Exporter in Prometheus?*
   *Answer:*  
   An exporter is a component or service that exposes metrics in a format that Prometheus can scrape. For example, the Node Exporter collects system-level metrics such as CPU, memory, and disk usage.

#### 4. *What is PromQL, and can you give an example?*
   *Answer:*  
   PromQL (Prometheus Query Language) is a query language used to extract and manipulate time-series data in Prometheus. Example query:  
   rate(http_requests_total[5m])  
   This query returns the per-second rate of increase in HTTP requests over the last 5 minutes.

#### 5. *How does Prometheus handle high availability?*
   *Answer:*  
   Prometheus itself does not natively support clustering for high availability. To ensure high availability, you can run multiple instances of Prometheus in parallel, each scraping the same targets. For alerting, Alertmanager can be run in a clustered mode to ensure high availability.

#### 6. *How do you scale Prometheus?*
   *Answer:*  
   Prometheus is designed for single-server scalability. To scale Prometheus for larger workloads:
   - Use *federation*, which involves setting up a Prometheus hierarchy with a central instance aggregating metrics from downstream instances.
   - Use *remote storage* to offload historical data to long-term storage solutions (e.g., Thanos or Cortex).
   - Run multiple Prometheus instances scraping different subsets of targets.

#### 7. *What are the limitations of Prometheus?*
   *Answer:*  
   - Lack of native clustering.
   - Prometheus is not suited for long-term storage of metrics; external storage is needed.
   - It uses a pull model, which may not be ideal for all use cases.
   - No built-in user authentication or role-based access control (RBAC).

#### 8. *What is the difference between Gauge and Counter in Prometheus?*
   *Answer:*  
   - *Gauge*: A metric that represents a single numerical value that can go up or down (e.g., memory usage).
   - *Counter*: A cumulative metric that only increases (e.g., the number of HTTP requests). It can be reset to zero upon restart.

#### 9. *What is a Prometheus alert, and how does it work?*
   *Answer:*  
   Alerts in Prometheus are defined in the rules file and are based on PromQL expressions. When a condition is met, the alert is triggered and sent to Alertmanager. Alertmanager can then group, deduplicate, and route the alerts to different receivers (e.g., email, Slack).

## Terraform Troubleshooting Questions

1. *Question*: What steps do you take if a Terraform plan fails?
   *Answer*: Review the error message in the output to identify the cause. Check for syntax errors in the configuration files, ensure all required variables are set, and validate that the necessary provider plugins are installed.
2. *Question*: How do you resolve issues with Terraform not recognizing changes in your infrastructure?
   *Answer*: Use terraform refresh to update the state file with the current infrastructure status. Ensure that the resource configuration has been changed correctly in the .tf files.
3. *Question*: What would you do if a Terraform apply command hangs indefinitely?
   *Answer*: Check for potential locks on the state file in the backend (e.g., S3, Consul) and verify the status of the infrastructure. Use CTRL+C to cancel and check logs for any resource-specific errors.
4. *Question*: How do you troubleshoot a situation where Terraform cannot find a resource?
   *Answer*: Verify the resource name and type in your configuration files. Check the resource’s existence in the cloud provider's console and ensure that the correct provider configuration is specified.
5. *Question*: What do you do if Terraform state file is corrupted?
   *Answer*: Restore the state file from a backup if available. Use terraform state commands to manipulate the state manually, or consider using terraform import to re-establish the resource state.
6. *Question*: How would you handle a situation where a resource cannot be deleted due to dependencies?
   *Answer*: Review the dependency tree using terraform graph or terraform state list to understand dependencies. Use terraform state rm <resource> to remove the resource from the state file if you need to force delete it.
7. *Question*: What steps would you take if your Terraform module is not working as expected?
   *Answer*: Check the module source path and ensure it is correctly referenced. Validate the input variables and outputs, and review any module-specific documentation for usage instructions.
8. *Question*: How do you resolve issues with provider authentication when running Terraform?
   *Answer*: Verify that the credentials are correctly configured in the provider block or through environment variables. Ensure that the permissions associated with the credentials are sufficient to manage the resources.
9. *Question*: What should you do if a Terraform plan shows changes that you did not expect?
   *Answer*: Review the Terraform state file and your configuration files for discrepancies. Check if there are any manual changes made to the resources outside of Terraform. Consider using terraform plan -out=<filename> to capture the changes for review.
10. *Question*: How do you troubleshoot variable issues in Terraform?
    *Answer*: Check that all required variables are defined and have values. Use terraform console to evaluate variable values at runtime, and ensure that the variable types match what is expected in your configuration files.

### Azure Troubleshooting Questions
1. *Q: A virtual machine (VM) fails to start. What steps would you take to troubleshoot this issue?*
   - *A:* Check the Azure portal for error messages related to the VM. Review the boot diagnostics logs, ensure that the VM is not in a "stopped (deallocated)" state, and verify that there are sufficient resources in the subscription and region. If applicable, check for issues with the attached disk.
2. *Q: You cannot connect to an Azure SQL Database. What could be the cause?*
   - *A:* Verify that the SQL Server firewall rules allow your IP address. Check the connection string for correct server name and database name. Ensure that the database is online and not in a "restoring" state.
3. *Q: An Azure Function is timing out. How do you diagnose and fix this?*
   - *A:* Check the timeout settings in the function app configuration and increase the timeout if necessary. Use Application Insights to monitor performance and identify bottlenecks in the code.

   - *A:* Check the deployment logs for errors. Common issues include incorrect configuration settings, missing application dependencies, or insufficient resources. Validate that the app service plan is correctly configured.
5. *Q: What do you do if a storage account is unreachable?*
   - *A:* Verify the storage account status in the Azure portal. Check the network configuration to ensure that it allows access from the relevant IP addresses or services. Investigate Azure Service Health for any outages in the region.
6. *Q: You receive an "insufficient quota" error when creating a resource. What steps can you take?*
   - *A:* Check the Azure subscription quota for the resource type. If the quota has been reached, request a quota increase through the Azure portal. Consider deleting unused resources to free up quota.
7. *Q: A load balancer is not distributing traffic as expected. What should you check?*

8. *Q: Your Azure Logic App fails to trigger. How do you investigate?*

9. *Q: An Azure VM is running slowly. What performance metrics should you check?*

10. *Q: You have configured Azure AD authentication, but users cannot log in. What could be wrong?*
    - *A:* Verify that the application is registered correctly in Azure AD and that permissions are granted. Check the application settings for valid redirect URIs and ensure that users have the necessary access permissions.

### Kubernetes Troubleshooting Questions

1. *Q: A pod is in a "CrashLoopBackOff" state. What could be the reason?*
   - *A:* This indicates that the container is crashing repeatedly. Check the pod logs using kubectl logs <pod_name> for error messages and ensure that the application configuration is correct.
2. *Q: Why might a Kubernetes service not route traffic to the pods?*
   - *A:* Check the service configuration and ensure that the selector labels match those of the pods. Verify that the pods are in a "Running" state and that there are no network policies blocking traffic.
3. *Q: You cannot access a pod from outside the cluster. What steps do you take?*
   - *A:* Check the service type (e.g., ClusterIP vs. LoadBalancer). For external access, ensure that a LoadBalancer service or NodePort is correctly configured. Verify firewall rules and network configurations.
4. *Q: A deployment fails to roll out. What should you check?*
   - *A:* Review the events of the deployment using kubectl describe deployment <deployment_name>. Look for any errors related to pod creation or scheduling.

5. *Q: How do you troubleshoot a failed job in Kubernetes?*
   - *A:* Check the job's status and logs using kubectl describe job <job_name> and kubectl logs <pod_name>. Look for reasons such as resource limits being exceeded or incorrect configurations.
6. *Q: A node is not scheduling any new pods. What could be the issue?*
   - *A:* Check if the node is in a "NotReady" state using kubectl get nodes. Investigate any resource constraints or network issues preventing the node from communicating with the control plane.
7. *Q: You see an "ImagePullBackOff" error for a pod. What should you do?*
   - *A:* Verify that the image name and tag are correct in the pod spec. Ensure that the image is available in the specified container registry and check if authentication is required.
8. *Q: What could cause a Kubernetes cluster to be unresponsive?*
   - *A:* Check the status of the control plane components (API server, etcd, controller manager). Look for resource exhaustion on nodes or network partition issues between nodes.
9. *Q: A persistent volume claim (PVC) is stuck in the "Pending" state. What should you check?*
   - *A:* Ensure that there are available persistent volumes that match the PVC's requested storage class and size. Check the storage class configuration for any misconfigurations.
10. *Q: How do you resolve a pod that is stuck in a "ContainerCreating" state?*
    - *A:* Use kubectl describe pod <pod_name> to check events for errors related to volume mounting, image pulling, or node resource availability. Address the underlying issue as indicated in the event logs.

Azure Cloud Computing

1. What is the purpose of Azure Resource Manager (ARM)?

Answer: Azure Policy is a service that helps enforce organizational standards and assess compliance at scale by applying policies on resources to control deployment and ensure compliance with regulatory standards.

Answer: Use Azure Key Vault to store and manage secrets securely, access policies to control access, and integrate Key Vault with applications and services to retrieve secrets, certificates, and keys securely.

5. What is the difference between Azure Active Directory (AAD) and Windows AD?

Answer: AAD is cloud-based identity and access management, whereas Windows AD is on-premises, focusing on managing resources within a network. AAD supports OAuth and OpenID for modern apps, while Windows AD uses Kerberos.

6. Describe the role of Azure Advisor.

Answer: Azure Advisor provides recommendations on high availability, security, performance, and cost based on best practices to optimize Azure deployments.

14. What are Azure Blueprints?

15. How can you enforce NSG rules in Azure for virtual networks?

17. What is the use of Availability Sets in Azure?

18. Explain the concept of Azure Front Door.

Answer: Azure Front Door is a global load balancer providing application acceleration, load balancing, and failover across Azure regions.

19. How can you achieve cost optimization in Azure?

Answer: Use Reserved Instances for consistent workloads, auto-scaling for VMs, shutting down idle resources, and regularly reviewing cost analysis in Azure Cost Management.

20. What are Service Endpoints and Private Endpoints?

Answer: Service Endpoints extend VNet identity to Azure services via the public IP space, while Private Endpoints provide a private IP to access services securely within the VNet.

Kubernetes

1. Explain the role of the etcd in a Kubernetes cluster.

Answer: etcd is a distributed key-value store used as Kubernetes’ backing store for all cluster data. It holds the configuration, state, and metadata of the cluster, enabling leader election, service discovery, and configuration management.



2. What is the difference between Deployment and StatefulSet in Kubernetes?

Answer: Deployments are for stateless applications, managing replica sets and rolling updates. StatefulSets are used for stateful applications, ensuring pods are created in a specific order and maintain unique identities (networking and storage).



3. Describe the function of a ConfigMap in Kubernetes.

Answer: ConfigMaps decouple environment-specific configurations from the application, allowing configurations to be injected into pods as environment variables or volumes without changing the pod image.



4. How would you troubleshoot a CrashLoopBackOff error in a Kubernetes pod?

Answer: Check pod logs with kubectl logs, review events with kubectl describe pod, verify resource limits, and inspect dependencies like network or service access that might cause repeated crashes.



5. What are Kubernetes Namespaces, and why are they used?

Answer: Namespaces partition a Kubernetes cluster into virtual clusters for resource isolation, helping segregate applications and enabling better resource management, especially in multi-tenant environments.



6. Explain the role of a DaemonSet in Kubernetes.

Answer: DaemonSets ensure that a specific pod is running on all (or some) nodes in the cluster, commonly used for log collection, monitoring, and networking services that need to run on every node.



7. What is the difference between NodePort and LoadBalancer services in Kubernetes?

Answer: NodePort exposes services on each node’s IP at a static port, accessible externally. LoadBalancer provisions a load balancer from the cloud provider to route external traffic to the service.



8. How does Horizontal Pod Autoscaler (HPA) work in Kubernetes?

Answer: HPA automatically scales the number of pods based on observed CPU utilization or custom metrics, adjusting resources to maintain performance under varying loads.



9. What is a Kubernetes Ingress, and how is it different from a LoadBalancer service?

Answer: Ingress manages external access to services, typically HTTP/HTTPS, allowing path-based routing. LoadBalancer exposes services to the internet via cloud provider load balancers without path-based routing.



10. How would you perform a rolling update in Kubernetes?

Answer: Using kubectl set image or editing the Deployment, Kubernetes will gradually replace old pod instances with new ones to ensure zero downtime, adhering to the defined strategy.



11. What are Kubernetes PersistentVolumeClaims (PVCs)?

Answer: PVCs are storage requests by users, binding to PersistentVolumes (PVs) that abstract physical storage, allowing pods to consume storage resources in a reusable manner.



12. How do you use Helm to manage applications in Kubernetes?

Answer: Helm is a package manager for Kubernetes that simplifies the deployment and management of applications through Charts, which define an application’s Kubernetes resources.



13. What is Kubelet, and what is its role in a Kubernetes node?

Answer: Kubelet is an agent running on each node that ensures containers are running in a pod, communicates with the master node, and performs health checks.



14. Explain the use of NetworkPolicies in Kubernetes.

1. What is Azure Hub and Spoke Networking?

Answer: Azure Hub and Spoke is a network architecture model used for structuring Virtual Networks (VNets) in a centralized way. The "Hub" represents a central VNet that connects to multiple "Spokes," which are other VNets. The Hub typically holds shared resources (like firewalls, VPN gateways, or DNS servers) and provides communication between Spokes.


2. Why is the Hub and Spoke model used in Azure networking?

Answer: The Hub and Spoke model offers several advantages:

Centralized Management: The Hub acts as a central point for networking and security, reducing the complexity of routing and management.

Isolation: Spokes can be isolated from each other while still allowing communication through the Hub.

Scalability: It simplifies the process of adding new Spokes without reconfiguring the entire network.

Security: You can apply security policies in the Hub to control traffic between Spokes.



3. What is a Hub in the Hub and Spoke model?

Answer: The Hub is typically a central VNet in the Azure architecture that connects all Spokes and contains shared resources such as network security appliances, VPN gateways, or DNS services. It's the central point for routing traffic between Spokes and to/from on-premises environments.


4. What is a Spoke in the Hub and Spoke model?

Answer: A Spoke is a VNet that connects to the Hub but does not directly communicate with other Spokes. Spokes are used for application workloads, different departments, or projects, and can be segmented for security and isolation.

Intermediate Level:

5. How does Azure VNet Peering work in Hub and Spoke architecture?

Answer: Azure VNet Peering allows the Hub VNet to communicate with Spokes. When you peer VNets in Azure, you establish a connection between them, enabling traffic to flow between the networks. In Hub and Spoke, the Hub VNet is typically peered with each Spoke, but Spokes do not peer with each other directly.


6. What is Transitive Peering, and how does it apply to the Hub and Spoke model?

Answer: Transitive Peering allows networks to communicate with each other through an intermediary (e.g., Hub VNet). In the Hub and Spoke model, traffic from one Spoke can transit through the Hub to reach another Spoke without direct VNet peering between the Spokes. This is important for simplifying the architecture and managing inter-Spoke traffic.


7. What are Network Security Groups (NSGs) in Azure, and how do they apply to Hub and Spoke architecture?

Answer: NSGs are used to define rules that allow or deny traffic to network interfaces (NICs), subnets, or VNets. In Hub and Spoke, NSGs can be applied at different levels (e.g., on individual Spokes or at the Hub) to manage traffic flow between Spokes and the Hub. NSGs provide fine-grained control over who can access which resources.


8. How do you manage traffic flow between Hub and Spoke networks securely?

Answer: To secure traffic between the Hub and Spokes, you can use:

Network Security Groups (NSGs) to control traffic at the subnet or VM level.

Azure Firewall in the Hub to inspect and filter traffic between Spokes.

Azure Bastion for secure remote access to VMs without exposing RDP/SSH ports.

Route Tables to define custom routing paths.


9. What is the difference between a Hub and Spoke architecture and a Mesh architecture in Azure networking?

Answer: In a Hub and Spoke model, the central Hub manages the routing and communication between Spokes. However, in a Mesh architecture, every VNet (Spoke) is connected to every other VNet, forming a web of interconnected VNets. Mesh architectures can be more complex to manage but provide direct communication between all networks without the central Hub.

UDRs are applied to the subnets in the Spokes and Hub to control how traffic is routed between the networks.

Alternatively, certificate-based authentication is another method to avoid using a client secret. This method requires using a certificate for authentication, which is more secure and suitable for automated deployments.

Steps for Using Certificate-Based Authentication:
Create a Service Principal with a Certificate: Instead of using a client secret, you can generate a certificate and associate it with the Service Principal.

To create a Service Principal with a certificate, use the following Azure CLI commands:

Generate a self-signed certificate (or use an existing certificate):

bash
Copy
openssl req -x509 -newkey rsa:2048 -keyout azure-key.pem -out azure-cert.pem -days 365
This creates a public/private key pair, where azure-cert.pem is the certificate and azure-key.pem is the private key.

Create the Service Principal and upload the certificate:

bash
Copy

This will create a service principal and associate the certificate with it. You will receive an output containing the App ID, Tenant ID, and the Certificate thumbprint.

Configure the Service Connection in Azure DevOps: In Azure DevOps, create a new Service Connection for Azure Resource Manager:

Choose Service Principal (Certificate) as the authentication method.
Provide the App ID, Tenant ID, and Certificate Thumbprint.
Instead of the client secret, use the certificate you generated and uploaded.

hcl
Copy

Agar tum **Terraform me `count` meta-argument ka use karke** multiple VMs bana rahe ho, **aur sirf 3rd VM (index `[2]`) delete karni hai**, to Terraform me `count` **index-based deletion support nahi karta**.  

### **🔹 Problem with `count`**
- `count` ek **fixed number** hai, jo **sequentially resources create karta hai**.
- Agar tum `count = 4` dete ho, to Terraform **4 VMs create karega**, aur agar tum `count = 3` kar doge, to **last VM delete hogi, beech wali nahi**.

---

## ✅ **Solution 1: Manually Delete 3rd VM from State & Cloud**
Agar tum **Terraform state aur Azure se sirf ek VM delete karna chahte ho** bina configuration badle, to:

### **Step 1: Check Existing VMs**
```sh
terraform state list | grep azurerm_virtual_machine
```
Maan lo output aisa hai:
```
azurerm_virtual_machine.example[0]
azurerm_virtual_machine.example[1]
azurerm_virtual_machine.example[2]  # <== Ye delete karni hai
azurerm_virtual_machine.example[3]
```

### **Step 2: Remove VM from Terraform State**
```sh
terraform state rm azurerm_virtual_machine.example[2]
```
⚠️ **Isse sirf Terraform state se remove hoga, par actual VM Azure me rahegi!**

### **Step 3: Manually Delete VM from Azure**
```sh
az vm delete --name vm-2 --resource-group my-rg --yes
```

### **Step 4: Run `terraform apply` to Sync State**
```sh
terraform apply -auto-approve
```
Ab Terraform **dubara VM-2 create nahi karega**, kyunki wo state me exist hi nahi karti.

---

## ✅ **Solution 2: Modify `count` with `for_each` for Future Flexibility**
Agar tum chahte ho ki **aage se bhi selective deletion easy ho**, to **`count` ki jagah `for_each` ka use karo**:

### **Step 1: Modify Code**
```hcl
variable "vm_list" {
  default = ["vm-0", "vm-1", "vm-3"]  # vm-2 hata diya
}

resource "azurerm_virtual_machine" "example" {
  for_each = toset(var.vm_list)
  name     = each.value
}
```
### **Step 2: Apply Changes**
```sh
terraform apply -auto-approve
```
✅ **Isse VM-2 automatically delete ho jayegi aur future me bhi changes asaan honge!**

---

## ❌ **Kya Directly `count` Se Sirf 3rd VM Delete Ho Sakti Hai?**
Nahi, **Terraform `count` me index-based deletion support nahi karta**. Agar tum `count = 4` se `count = 3` karoge, to **VM-3 delete hogi, VM-2 nahi**.

### **Incorrect Way (Won't Work)**
```hcl
resource "azurerm_virtual_machine" "example" {
  count = 3  # ❌ Isse sirf last VM delete hogi, beech wali nahi
  name  = "vm-${count.index}"
}
```
Agar tum VM-2 delete karna chahte ho, to ya to **`terraform state rm` + manual delete** karo, ya **`for_each` approach use karo**.

---

## **🔹 Summary**
| Approach | Works? | Explanation |
|----------|--------|-------------|
| `terraform state rm` + Manual Deletion | ✅ Yes | Sirf ek VM remove karega bina config badle |
| `for_each` Instead of `count` | ✅ Best | Selective deletion future me easy ho jayega |
| Reduce `count = 3` | ❌ No | Sirf last VM delete hogi, VM-2 nahi |

🌱 Root Module vs. Child Module in Terraform
In Terraform, every configuration has at least one module:

The Root Module is the main entry point.
The Child Module is any module called within the root module.

📌 Root Module (Top-Level Module)
✅ Definition:
The Root Module is the main Terraform configuration where execution starts.
✅ Location:
It is the directory where you run terraform init and terraform apply.
✅ Contains:

main.tf, variables.tf, outputs.tf, terraform.tfvars
Calls child modules inside the modules/ folder
📌 Example: Root Module (main.tf)

h
Copy
Edit
provider "azurerm" {
  features {}
}

  source = "./modules/network"
  vnet_name = "my-vnet"
  location  = "East US"
}

module "compute" {
  source    = "./modules/compute"
  subnet_id = module.network.subnet_id
}



Child Module (Reusable Module)
✅ Definition:
A Child Module is a module called by another module, typically by the root module.
✅ Purpose:

Encapsulates specific functionalities (e.g., networking, compute, storage).
Reusable across multiple Terraform projects.
✅ Location:
Usually stored inside a modules/ directory.

Meta Argumets in terraform : 

These do not modify resource behavior but control how Terraform manages resources.

✅ List of Key Terraform Meta-Arguments
Meta-Argument	Description
count	        Creates multiple resources based on a number.
for_each	Creates multiple resources based on a set, map, or list.
depends_on	Ensures resource dependency execution order.
lifecycle	Controls resource lifecycle (e.g., prevent deletion, ignore changes).

🔍 Difference Between variables.tf and terraform.tfvars in Terraform
Both variables.tf and terraform.tfvars are used to manage variables in Terraform, but they have different purposes.

📌 1️⃣ variables.tf (Variable Declaration)
This file is used to declare variables.
It does not assign values—it only defines variable types, descriptions, and defaults.
Typically named variables.tf or vars.tf.

This only declares variables; it does not provide values (except defaults).

.

📌 2️⃣ terraform.tfvars (Variable Assignment)

This file is used to assign values to variables.
Terraform automatically loads values from terraform.tfvars if it exists.
You can also use other .tfvars files (e.g., dev.tfvars, prod.tfvars) to manage environments.

Local variable and local blocks : 


The locals block in Terraform is used to define local variables that store values within a module or configuration. These values cannot be overridden externally like input variables but help reduce repetition and improve readability.

A local variable in Terraform is used to store computed values within a module to make the configuration cleaner and avoid repetition.Unlike input variables (variable "name" {}), locals are defined inside the configuration and cannot be overridden externally. 

eg 
locals {
  region        = "eastus"
  instance_type = "Standard_B2s"
  tags = {
    Environment = "Dev"
    Owner       = "TeamA"
  }
}

resource "azurerm_virtual_machine" "vm" {
  name                = "my-vm"
  location            = local.region   # Using local variable
  instance_type       = local.instance_type
  tags               = local.tags     # Using local map
}
